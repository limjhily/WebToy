## 0. 먼저 읽을 다섯 가지

리서치 중 **계획 자체를 바꿔야 하는 사실**이 다섯 개 나왔습니다. 아이디어 목록보다 이게 먼저입니다.

### ① 애드센스는 시작점일 뿐, 종착점이 아니다

광고 네트워크는 사다리 구조입니다. 트래픽이 쌓이면 갈아타야 하고, 갈아타면 수익이 5~10배가 됩니다.

| 네트워크 | 진입 조건 | RPM (1,000회 노출당) |
|---|---|---|
| Google AdSense | 없음 | **$1~5** |
| Mediavine Journey | 월 1만 세션 | 중간 |
| Raptive | 월 **2.5만 페이지뷰** (2025.10 인하, 기존 10만) | **$18~26** |
| Mediavine 본 플랫폼 | **연 광고수익 $5,000** | **$15~40+** |
| Ezoic | 월 25만 사용자 (2026.2 대폭 상향) | $5~15 |

**함의**: 목표는 "애드센스 승인"이 아니라 **"월 2.5만 페이지뷰"** 입니다. 거기서 수익이 4~5배 뜁니다.

### ② 그런데 Raptive에는 한국어 사이트를 가로막는 조건이 있다

월 2.5만~10만 페이지뷰 구간은 **Tier-1(미국·영국·캐나다·호주) 트래픽이 50% 이상**이어야 합니다. 순수 한국어 사이트는 월 10만 페이지뷰를 넘기 전까지 이 문턱을 넘을 수 없습니다.

**함의**: 영어판 병행은 "선택"이 아니라 **수익 사다리를 오르기 위한 필수 조건**입니다. 이전 계획서에서 3군으로 미뤄둔 영어판을 앞으로 당겨야 합니다.

### ③ 애드센스 승인을 기다리는 동안에도 돈은 벌 수 있다

쿠팡파트너스는 승인 절차가 훨씬 가볍고 **애드센스 승인 전에도 배너를 달 수 있습니다.** 수수료는 거래액의 3%, 링크프라이스는 2~10%에 쿠키 기간도 깁니다. 심사 대기 2~4주가 공백일 필요가 없습니다.

### ④ 해외 1등들은 광고가 아니라 제휴로 번다

- **MoneySavingExpert**(영국): 2012년 **£8,700만에 매각**. 매각 직전 월 1,300만 방문, 매출 £15.7M인데 **수익의 59%가 제휴**였습니다. 직원 42명 중 절반이 기자였습니다.
- **価格.com**(일본): 월 5,000만 방문, **영업이익률 48.9%**. 수익 3축이 쇼핑 수수료 + 견적 수수료(보험·금융·중고차) + 광고입니다.
- **Canstar**(호주): 연 매출 $40M. CPC 수수료에 더해 **금융기관이 DB를 구독**합니다.
- **Numbeo**(세르비아): 크라우드소싱으로 모은 데이터를 **API로 판매**합니다.

**함의**: 계산기는 트래픽을 모으는 입구이고, 진짜 수익은 그 뒤에 붙는 제휴·견적·데이터입니다. 처음부터 그 구조를 염두에 두고 설계해야 합니다.

### ⑤ 계산기 하나의 경제적 가치는 생각보다 크다

- SmartAsset의 **급여 계산기 한 페이지**가 월 유기 방문 69만, 트래픽 가치 **$110만**입니다.
- NerdWallet은 **주(州)별로 급여 계산기를 복제**하는 프로그래매틱 SEO를 씁니다. 복리 계산기 하나가 월 28.9만 방문입니다.
- Wise는 통화쌍마다 페이지를 만들어 **3,000개 이상**을 운영합니다.

**함의**: "계산기 6종 + 글 5편"이 아니라, **하나의 계산기를 조건별로 수백 페이지로 분화**시키는 것이 트래픽 곱셈의 핵심입니다. 한국이라면 시군구별·차종별·평형별·연봉구간별입니다.

|---|---|---|

| **B. 역산과 시뮬레이션** | 기존은 전부 단방향. 거꾸로 묻고 조건을 바꿔 보고 싶다 | 일본 ふるさと納税 포털 전부가 "공제상한액 시뮬레이터"를 입구로 씀 |
| **C. 장벽 제거** | 로그인·업로드·설치가 벽이다 | 공단 공동인증서, 온라인 도구의 서버 업로드 |
| **D. 가격 투명성** ★신규 | 가격 데이터는 공개돼 있는데 쓸 수 있는 형태가 아니다 | **GoodRx**: 약값 비교로 누적 $850억 절감, 연 3,000만 명. 재구매 80% |
| **E. 시장가치 진단** ★신규 | "남들은 얼마 받나"를 알고 싶다. 공유 욕구가 강해 바이럴이 된다 | **Levels.fyi** 월 300만 명. **doda 年収査定**은 186만 명 전직 데이터로 적정연봉 진단 |
| **F. 프로그래매틱 확장** ★신규 | 하나의 도구를 데이터 차원으로 쪼개 수백~수천 페이지로 | Wise 3,000+, Zapier 25,000+, G2 100,000+ |

# 그룹 A — 해외에서 검증된 모델의 한국 이식

## A1. 고향사랑기부 시뮬레이터 + 답례품 비교 ★★★

**해외 근거**: 일본 고향납세(ふるさと納税)는 2020년 기부액 **약 7조 원**. さとふる·ふるなび·マイナビ 등 주요 포털이 **전부 "공제상한액 시뮬레이터"를 사이트 입구로** 씁니다. 사용자는 "내가 얼마까지 기부하면 자기부담 2,000엔으로 끝나는가"를 알고 싶어 하고, 그 계산이 곧 유입 경로입니다.

**한국 현황**: 2023년 도입, 2025년 모금 **1,515억 원 / 139만 건**. 일본보다 10년 이상 늦었고 규모는 40분의 1입니다. 2026년부터 **10만 원까지 100% 전액 세액공제, 10~20만 원 구간 44% 공제**로 개편됐고, 2027년부터는 인구감소지역 기부에 공제율을 더 얹습니다. 연간 최대 2,000만 원까지 기부 가능하고 답례품은 기부액의 30% 한도입니다.

**빈틈**: 공식 창구인 **고향사랑e음은 구축비 70억 원을 쓰고도 절차가 복잡하고 오류가 잦으며, 연말정산 시기에 시스템이 마비**됩니다. 지자체 담당자는 1~3명뿐이라 홍보도 안 됩니다. 상·하위 30위 지자체 간 모금액 격차가 21배입니다. 일본식 시뮬레이터에 해당하는 서비스가 한국엔 사실상 없습니다.

**만들 것**
1. **공제 한도 시뮬레이터** — 연봉·부양가족을 넣으면 "자기부담 없이 기부할 수 있는 최대 금액"이 나옴. 2026 개편(10만원 100% / 10~20만원 44%) 반영
2. **답례품 가성비 비교** — 기부액 대비 답례품 시가를 계산해 정렬. 지자체별 답례품을 모아 검색 가능하게
3. **지자체별 페이지 (패턴 F)** — 229개 시군구 × 답례품 목록 = 수백 페이지 프로그래매틱 SEO
4. **연말 마감 카운트다운** — 12월 쏠림이 심한 제도이므로 시즌성 트래픽이 확실

**수익성**: 단가 4점(금융·세금). 12월 집중형이지만 매년 반복. 장기적으로는 답례품 제휴 가능성.
**난이도**: 중. 답례품 데이터는 고향사랑e음에서 수집 필요(크롤링 정책 확인 필요).

## A2. 비급여 진료비 비교 — 한국판 GoodRx ★★★

**해외 근거**: **GoodRx**는 약값 비교 하나로 연 3,000만 명이 쓰고 누적 $850억을 절감시켰습니다. 매출의 76%가 처방 거래 수수료이고 **재구매가 80%**입니다. 핵심은 "가격이 공개돼 있지만 소비자가 비교할 수 없는 상태"를 푼 것입니다.

**한국 현황**: 2026년 9월 3일부터 심평원이 **전국 7만 4,449개 의료기관의 753개 비급여 항목** 가격을 공개했습니다. 격차가 큽니다.

| 항목 | 최저 | 최고 |
|---|---|---|
| 체외충격파치료 | 7만 원 (경기) | 17만 5천 원 (서울) |
| 지르코니아 임플란트 | 110만 원 (경남) | 172만 원 (서울) |

2025년 대비 비교 가능한 593개 항목 중 **436개(73.5%)가 가격 상승**했습니다.

**검증 결과**: 공공데이터포털에 **"건강보험심사평가원_비급여진료비정보조회서비스" 오픈API가 실재**합니다(비급여항목코드, 항목별 병원목록, 종별·지역별 진료비용). 다만 **병원급 이상**이 중심이라 의원급 커버리지는 확인이 필요합니다. 심평원 누리집과 건강e음 앱이 있지만 UI가 불편하고 비교 목적에 맞지 않습니다.

**만들 것**
1. **항목별 지역별 가격 비교** — "도수치료 강남구" 같은 검색에 바로 답하는 페이지
2. **패턴 F 적용** — 753개 항목 × 229개 시군구 조합에서 검색량 있는 것만 추려도 수천 페이지
3. **실비보험 보장 여부 병기 (패턴 A)** — 비급여 항목마다 실손보험에서 보장되는지, 몇 세대 실비인지에 따라 어떻게 다른지를 가격 옆에 표시. **이게 진짜 차별점입니다.** 사람들이 알고 싶은 건 가격이 아니라 "내가 실제로 얼마 내나"입니다
4. **가격 추이** — 전년 대비 인상률 표시

**수익성**: 단가 4~5점(의료·보험). 트래픽 5점. **이 목록에서 가장 유망합니다.**
**난이도**: 중상. API 연동 + 데이터 갱신 파이프라인 필요.
**주의**: 의료광고법상 특정 의료기관을 유리하게 표현하면 안 됩니다. 공공데이터를 중립적으로 표시하는 선을 지켜야 합니다.

## A3. 내 연봉 시장가치 진단 ★★★

**해외 근거**: **Levels.fyi**는 2017년 사이드 프로젝트로 시작해 월 **300만 명**이 씁니다. 시작점은 "회사마다 직급 체계가 달라 비교가 안 된다"는 흩어진 정보 문제였습니다. 일본 **doda 年収査定**은 **186만 명의 전직자 데이터**로 머신러닝 적정연봉을 산출하고, **ミイダス**는 시장가치 진단 후 기업에서 오퍼가 오는 구조입니다.

**한국 현황**: 블라인드·잡플래닛·사람인에 데이터는 있으나 **"내 연봉이 동일 직무·경력·지역에서 몇 퍼센타일인가"를 보여주는 곳이 없습니다.** 연봉 협상은 68%가 일방 통보이고, 조정 신청한 사람의 48%는 인상에 성공했습니다. 즉 근거가 있으면 올릴 수 있는데 근거가 없습니다.

**만들 것**
1. **백분위 진단** — 직무·경력·지역·회사규모를 넣으면 "상위 몇 %"와 분포 그래프. 고용노동부 임금직무정보시스템 등 공개 통계 기반
2. **결과 카드 공유 (패턴 E)** — 공유 욕구가 강한 콘텐츠. 이 저장소의 마음카드 기술(URL에 데이터 압축)을 그대로 재활용 가능
3. **협상 근거 시트 생성** — 진단 결과를 협상에 쓸 수 있는 한 장짜리 요약으로
4. **직무별 페이지 (패턴 F)** — "백엔드 개발자 5년차 연봉", "간호사 3년차 연봉" 식으로 수백 페이지

**수익성**: 단가 3~4점(채용·금융·교육). 트래픽 5점. 바이럴 가능성 최상.
**난이도**: 중. 데이터 신뢰성이 관건이며, 출처와 표본을 반드시 명시해야 합니다.

## A4. 한국판 생활 시뮬레이터 허브 (くらしの計算機 모델) ★★

**해외 근거**: 일본 **くらしの計算機**는 연금 수령 개시연령 최적 판정, 100세까지 라이프플랜 통합 시뮬레이션, 가계 배분 계산 등 "인생 단위" 계산을 모아 둡니다. **금융청이 직접 라이프플랜 시뮬레이터를 운영**할 만큼 수요가 검증된 영역입니다. **エネチェンジ**는 우편번호 단위 기상 데이터와 세대 인원까지 반영해 전기요금을 시뮬레이션합니다.

**한국 빈틈**: 한국엔 단발 계산기는 많은데 **생애 단위 통합 시뮬레이션이 없습니다.**

**만들 것**
1. **은퇴 시뮬레이터** — 현재 자산·소득·저축률을 넣으면 몇 살에 은퇴 가능한지, 국민연금 개혁 반영
2. **연금 수령 개시 최적화** — 조기수령 vs 연기수령 손익분기 나이
3. **생애 현금흐름 표** — 결혼·출산·주택구입·교육비·은퇴를 타임라인에 얹어 적자 구간 표시
4. **전기요금은 지역·계절 반영** — 여름 7~8월 1단계 구간이 200→300kWh로 확대되는 것까지

**수익성**: 단가 4점(금융·보험). 난이도 중.

## A5. 종합 비교 사이트 (Check24 / 価格.com 모델) ★

# 그룹 E — 영어권 도구 (Raptive Tier-1 조건 충족용)

앞서 말한 대로 Raptive 진입에는 **Tier-1 트래픽 50% 이상**이 필요합니다. 이 그룹은 수익 사다리를 오르기 위한 전략적 투자입니다.

## E1. 프라이버시 우선 개발자 도구 ★★★

**근거**: 개발자들이 온라인 JSON 포맷터에 **프로덕션 API 응답, 설정 파일, DB 덤프, 액세스 토큰, 고객 레코드**를 붙여넣습니다. 데이터가 서버 로그와 애널리틱스에 남고 유출 시 노출됩니다. **대부분의 기업 보안정책이 미승인 외부 도구 사용을 금지**하고, GDPR/CCPA상 제3자 서버 처리는 DPA 대상이 될 수 있습니다. 개발자들은 DevTools에서 네트워크 요청이 없는지, 인터넷을 끊고도 동작하는지로 검증합니다.

**우리의 진짜 강점**: 정적 사이트라 **실제로 서버 전송이 없습니다.** 이건 마케팅 문구가 아니라 사실입니다.

**만들 것**: JSON 포맷터·검증, Base64, URL 인코딩, 정규식 테스트, 해시, JWT 디코더, 색상 변환, cron 해석, diff, UUID, 타임스탬프 변환. 페이지에 **실시간 네트워크 요청 카운터**를 띄우고 DevTools 확인법을 안내.

**수익성**: 단가 4점(SaaS 광고). Tier-1 트래픽 확보에 최적.

## E2. 오프라인 PDF·이미지 도구 ★★
ilovepdf(월 2.26억)·smallpdf는 전부 서버 업로드 방식입니다. 2시간 내 삭제를 명시해도 파일이 네트워크를 건너간다는 사실은 변하지 않습니다. 계약서에 주민번호·주소가 들어 있으면 곤란합니다. pdf-lib·pdf.js로 브라우저에서만 처리하고 같은 증명 UI를 붙입니다.

## E3. AI 비용 계산기 ★★
토큰 경제가 화두입니다. **한국어는 영어보다 같은 내용에 토큰이 더 많이 듭니다.** 모델별 가격 비교 + 한국어 토큰 특성을 다루는 계산기는 한국어·영어 양쪽에서 틈새입니다.

## E4. Numbeo형 생활비 비교 ★
Numbeo는 4,400개 도시 데이터를 모아 **API로 판매**합니다. 한국 도시 단위 생활비 데이터를 크라우드소싱으로 모으면 장기적으로 데이터 자산이 됩니다. 다만 초기 데이터 확보가 어려워 후순위.

## E5. 글로벌 공휴일·시차 ★
timeanddate가 강자지만 한국 기준 "한국에서 X국가로 출장" 같은 조합은 틈이 있습니다.

## 3. 서비스 구축 방법

### 3-1. 기술 구조 — 왜 정적 사이트인가

| 항목 | 선택 | 이유 |
|---|---|---|
| 호스팅 | Cloudflare Pages | 무료, 무제한 대역폭, 전 세계 CDN |
| 빌드 | 없음 (순수 HTML/CSS/JS) | 초보자가 유지보수 가능. 빌드 실패로 사이트가 죽을 일이 없음 |
| 계산 | 전부 브라우저에서 | 서버 비용 0원. **E1·E2의 "네트워크 요청 0회"가 사실이 되는 근거** |
| 데이터 | JSON 파일을 저장소에 커밋 | DB 불필요. 갱신은 GitHub Actions가 자동으로 |
| 공용 코드 | `shared/` → `tools/sync-shared.js`로 각 사이트에 복사 | Cloudflare Pages는 사이트 폴더만 배포하므로 상위 폴더 참조 불가 (구축 완료) |

이 구조의 진짜 장점은 **월 운영비가 도메인 값뿐**이라는 것입니다. 트래픽이 100배가 돼도 비용이 늘지 않습니다.

### 3-2. 데이터 파이프라인 — 공공데이터를 자동으로 최신 유지

```
공공데이터포털 API  →  GitHub Actions (매일/매주 크론)
                        ↓ 수집·정제
                    data/*.json 자동 커밋
                        ↓
                  Cloudflare Pages 자동 재배포
```

- **공공데이터포털(data.go.kr)** 에서 API 키를 받습니다. 국토부 아파트 실거래가는 **자동승인**이라 신청 즉시 씁니다. 심평원 비급여진료비정보조회서비스도 여기 있습니다.
- GitHub Actions에 스케줄을 걸어 수집 스크립트를 돌리고, 결과 JSON을 저장소에 커밋합니다. 커밋되면 Cloudflare Pages가 자동으로 재배포합니다.
- 서버가 없으므로 **API 키가 브라우저에 노출될 일이 없습니다.** 수집은 GitHub Actions 안에서만 일어나고, 사용자는 정제된 JSON만 받습니다. 이건 보안상 중요한 구조입니다.
- 갱신 주기: 세율·요율은 연 1~2회 수동, 실거래가·진료비는 주 1회 자동.

### 3-3. 프로그래매틱 SEO 구현 (그룹 D)

1. **데이터셋 준비** — 예: 229개 시군구 코드와 이름, 각 지역의 세율·평균값
2. **템플릿 1개 작성** — 변수가 들어갈 자리를 표시한 HTML
3. **생성 스크립트** — Node 스크립트가 데이터 × 템플릿으로 HTML 파일을 찍어냄
4. **sitemap.xml 자동 생성** — 페이지 수가 많으면 5만 개 단위로 분할하고 sitemap index 사용
5. **내부 링크** — 각 페이지에서 인접 지역·관련 조건 페이지로 연결. 이게 색인에 결정적

**반드시 지킬 것**: 페이지마다 그 조건에만 해당하는 **고유한 데이터와 설명 200자 이상**. 숫자만 바꾼 껍데기 페이지를 대량 생산하면 애드센스 저품질 판정과 구글 색인 제외를 동시에 맞습니다. 처음엔 검색량이 확인된 50~100페이지만 만들고, 색인이 잘 되면 늘리는 방식이 안전합니다.

## 5. 판단이 필요한 것

1. **영어판을 실제로 할 것인가** — Raptive 3단계(RPM 4~5배)에 들어가려면 필요하지만, 한국어 사이트보다 콘텐츠 작성 부담이 큽니다.
2. **사이트를 몇 개로 갈 것인가** — 도메인당 1개 원칙은 유지하되, B4+B5(평형+이사), B7+B8(노무+세무)처럼 주제가 붙는 것은 한 사이트로 묶는 게 승인과 SEO 양쪽에 유리합니다.
3. **데이터 파이프라인 사이트(A2·B2)를 언제 시작할 것인가** — 효과는 가장 크지만 선행 작업이 2~3주 걸립니다.
4. **1차 4개를 동시에 갈 것인가, 하나씩 검증할 것인가** — 애드센스 계정은 하나이고 한 사이트의 정책 위반이 계정 전체에 영향을 줍니다.
